# Audit, technical, and fix

Run framework, route, metadata, sitemap, robots, JSON-LD, links, evidence-ledger, and regression checks where applicable. Audit technical, on-page, content, schema, AEO, and conditional local/ecommerce concerns. Every finding has severity (CRITICAL/HIGH/MEDIUM/LOW/INFO), evidence label (observed/inference/hypothesis/unavailable), impact, recommended fix, automation level, and path.

Run `python3 scripts/full_audit.py <project> --score`; never hand-compute the 100-point score. It reads the versioned breakdown in [references/scoring-rubric.md](../references/scoring-rubric.md) (technical 20, IA 10, on-page 15, content 15, links 10, schema 10, performance 5, local 5, AEO 10). A category with no supporting evidence is excluded from the denominator, not scored zero — report both `score` (over evidenced max) and `coveragePct`, and always the label "internal prioritization, not a ranking prediction." If `checks.state.result.findings` reports content/keyword strategy as NOT STARTED, surface that explicitly rather than letting it sit silent. A finding may carry an optional `pattern` field (a P-id from [references/winning-patterns.md](../references/winning-patterns.md)) when `scripts/pattern_match.py` matched it — cite the pattern in its required form, never as a guaranteed fix outcome. `fix` implements only safe, evidenced items and leaves review-first items as a proposal.
