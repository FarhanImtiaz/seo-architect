# Security posture

This skill runs entirely offline by default and never requires a paid API or network access. Where it does touch the network (opt-in only), these rules apply:

- **Credentials come from the environment only, never a file or a URL.** `PSI_API_KEY`, `CRUX_API_KEY` are read from `os.environ` and sent in the `X-goog-api-key` header, never appended to a URL query string (which can leak via server/proxy logs, browser history, or shell history if echoed). Error messages are redacted (`scripts/live_data.py`'s `_redact`) before being printed, so a failed request can't leak a key through its exception text.
- **Every CSV/ZIP import is scanned for secret-shaped values before being written to disk** (`scripts/live_data.py`'s `_rows_have_secret`), across every row, not a sample.
- **Network use is opt-in per command, never automatic.** `psi`, `crux`, `competitor_diff.py`'s fetches, and `impact.py events fetch-google` all require an explicit invocation with explicit arguments; nothing in a normal `audit`/`optimize`/`schema` workflow reaches the network.
- **`scripts/competitor_diff.py`'s SSRF guard** resolves the target hostname via DNS (`ipaddress.*.is_global`, refusing anything private/loopback/link-local/reserved/multicast/CGNAT) and connects to the exact IP that check just validated — the connection is pinned to that IP (via a direct `http.client` connection, with the real hostname sent separately as the `Host` header and, for HTTPS, as the SNI/certificate-validation name), never re-resolving the hostname for the actual request. This closes the DNS-rebinding TOCTOU where a hostname could resolve to a public IP at check time and a private one at connect time. Every redirect hop is independently re-guarded before being followed (up to 5 hops) — a 3xx response pointing at an internal target is refused at that hop, not silently followed. It also respects the target's robots.txt (fetched through the same guarded/pinned path), uses an honest identifying User-Agent, caps response size at 3MB, and rate-limits to one request per 2 seconds.
- **`scripts/scan_logs.py` never persists a raw IP address.** Every IP is truncated (IPv4: last octet zeroed; IPv6: last 80 bits zeroed) before any aggregate is written to `.claude/seo/`, and the raw log file itself is never copied into project state.
- **Measurement data is gitignored by default.** `scripts/init_state.py` scaffolds `.claude/seo/measurement/.gitignore` so imported GSC/GA4/Bing/CrUX data (which can contain real query/page/session data) isn't accidentally committed; a user who wants it versioned has to deliberately remove that ignore rule.
- **The GitHub Action template never uses `pull_request_target`.** That trigger runs with the base repository's secrets and permissions against a PR's (possibly untrusted) code — this skill's CI check has no need for that and the template is deliberately built around `pull_request` with a minimal `permissions: contents: read` block instead.
- **`scripts/ci_check.py` never mutates the caller's real project state.** Both the base and head audits run against disposable scratch copies, so running a CI check can never silently overwrite a real `.claude/seo/baseline.json` as a side effect.

If you're extending this skill: keep new network-touching code to explicit, user-initiated commands; keep credentials in headers and environment variables, never in URLs, files, or committed state; and add a redaction/truncation step before persisting anything derived from a credential or a raw client identifier (IP, session ID).
